# 树莓派网页实时预测：第一版

采集设备仍由原 ae_project/main.py 控制；原 web_server.py 的采集、停止、下载和删除接口也不改动。新入口 web_with_prediction.py 复用原 Flask 应用，仅增加只读预测接口和页面。页面每 5 秒更新最近一组采集文件的临时结果。

数据流：设备 → ae_project/data_storage/同名 .pridb + .tradb → live_prediction_10.20.js → /api/prediction/latest → 网页面板。

## 使用的文件

- ae_project/web_with_prediction.py：新网页入口和只读 API。
- ae_project/templates/index_with_prediction.html：保留原控制面板并显示最新预测。
- 距离预测-1/live_prediction_10.20.js：只读 SQLite 特征和波形元信息，不加载大波形数据。
- 距离预测-1/predict_distance_10.20.js：原电脑端预测器；仅增加可复用的函数导出，原命令行用法不变。
- 距离预测-1/distance_model_summary.json、detection_parameters_10.20.json：来自 10.20亚克力 的标定参数。运行时不用把 31 组原始标定数据库拷到树莓派。

## 在树莓派上启动

保持上述两个文件夹的相对位置；若位置不同，设置 PREDICTOR_DIR 为 距离预测-1 的绝对路径。Python 虚拟环境仍使用原网页程序的 Flask 和 psutil。Node.js 需支持内置 node:sqlite，可先运行：

```
node -e "require('node:sqlite'); console.log('sqlite OK')"
```

进入 ae_project 目录，运行：

```
PREDICTOR_DIR=/实际路径/距离预测-1 ./venv/bin/python3 web_with_prediction.py
```

若原网页通过 systemd 启动，只需把该服务的启动脚本由 web_server.py 指向 web_with_prediction.py，工作目录仍是 ae_project；原 main.py 和采集参数代码不变。回退时把启动脚本改回 web_server.py。

网页地址仍是原来的 5000 端口。新接口是 /api/prediction/latest。可先直接用单个文件测试：

```
node /实际路径/距离预测-1/live_prediction_10.20.js /实际路径/ae_project/data_storage/某次采集.pridb
```

## 结果边界

- 采集中显示的是临时估算；随着事件增加，距离可能变化。第一版只读 .pridb 特征和 .tradb 的采样元信息，不计算完整波形频谱，尚不作为最终复核结论。
- 只有同名文件成对、有效事件至少 30 条、波形为 2 MHz 且每条 200,000 点时才显示数值距离。超出标定范围时不显示外推数值。
- 10.20亚克力 是固定对照标准，不是网页预测时反复读取的输入；新的设备采集文件只作为待预测输入，不进入标定数据。
- 探头、增益、滤波、角度和耦合条件也应与标定一致；仅采样率和点数相同并不足以证明现场预测准确。
